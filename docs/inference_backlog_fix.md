# 推理积压修复

## 执行

单个新增帧仍使用 CUDA Graph。多个新增帧使用 StreamingTCN 的整段批量前向，复制现有缓存字典（不复制 GPU 数据）作为起点；计算完成后原地回写 Graph 固定缓存。下一次单帧 replay 沿用正确历史。首次满窗初始化不变。不跳帧、不补假帧，不修改训练或权重。

## 诊断线程

分段分位数及推理总耗时分位数在独立线程每秒计算；控制线程只在短锁内追加最近300条记录，发布时读取汇总缓存。报告退出前停止后台线程并刷新最终结果。后台线程仍可能争用 CPU，不保证诊断零开销。

统计范围从已发送动作改为完成的推理尝试，包含 discarded/not_sent；抛异常、未返回预测的调用尚不计入。总推理分位数的窗口统一为最近300次，不应直接与旧5000条成功动作样本比较。

新增控制循环诊断：取队列、观测构建、发布耗时、循环耗时、取回帧数、推理前观测年龄、推理后落后帧数。循环从入口等待后开始，到发布完成为止，不包括入口轮询等待与统计追加。各分位数不能相加，CUDA 时间线不等于纯 kernel 时间。

保存报告时输出 inference_timing.json（最近300条原始诊断）及 summary.json。实时日志不逐帧落盘。页面需重新构建、服务需重启。模型与配置不需迁移。

按要求未运行测试、编译或游戏。已有 Graph 测试覆盖256帧初始化、1/3/2帧交替及重置，但仍待执行。下一步人工对比同模型的单帧稳态和多帧追赶、缓存连续性、总循环 P50/P95；没有承诺已达到60Hz。
