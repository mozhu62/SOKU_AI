# CQL 模型实战使用与评估

## 1. 和训练有什么区别

`scripts/train.py` 在 Windows/Linux 读取 NPZ 离线训练；`scripts/play.py` 只在 **Windows 游戏电脑** 运行。实战已改成复用 PPO 的浏览器工作台布局、顶部控制、逐局图表、模型选择和评估对比，不再使用 Tk。它与离线训练共用 `web` 前端项目、组件和依赖，生成 `index.html`（训练）与 `play.html`（实战）两个入口。

实战网页默认 `http://127.0.0.1:8777/play.html`，端口冲突自动递增；不需要 token。键盘控制仅监听本机，离线训练原有的局域网访问方式不变。没有部署到公网。

实战读取 checkpoint 的 `online` 网络与训练集归一化参数，严格校验输入结构和动作空间，采用 `eval()`、`inference_mode()` 和固定权重。不会创建优化器，不会更新参数，不会覆盖 `last.pt`。不需要把 NPZ、REP 或训练服务器的绝对目录复制回来。旧 PPO/DQN 项目保持不变，实战模块不导入它们。

离线的 `best.pt` 是按照离线验证指标选出的版本，不代表一定最会打。可以在相同人机难度、角色和决策间隔下分别评估 `best.pt`、`last.pt` 和历史版本，以完整小局的平均伤害差优先、胜率辅助比较，并查看波动和样本量。

## 2. 启动

1. 将训练服务器的完整 CQL `.pt` 文件复制到 Windows，桌面或任意数据盘均可，不必固定放到项目。请等 checkpoint 保存完成后复制。
2. Windows 项目使用 Python 3.11+ 及原有依赖；没有安装时由使用者执行 `python -m pip install -e .`。没有新增 Python GUI 依赖。网页源码更新后需要使用者手动构建；首次未安装依赖时先执行 `npm --prefix web ci`。
3. 正常启动已加载 `SokuDataBridge.dll` 的游戏。旧 CQL 使用 `Local\SokuDataBridge.State.v3`；新资源版模型还需要新版 DLL 的 `Local\SokuDataBridge.Resources.v1.<PID>` 技能通道，两个数据源严格同帧配对。不需要 PPO 专用帧队列。请由使用者手动编译安装新 DLL 并重启游戏；不要用批量 REP 转换脚本启动这一局，不要同时开多个采集/控制游戏实例。
4. 进入本地人机模式，默认 1P 萃香、2P CPU 灵梦。游戏内设置与实战窗口按键一致。
5. 在 `soku_cql` 目录执行：

```text
npm --prefix web run build
python scripts/play.py
```

打开终端打印的浏览器链接。初始配置路径存在时会尝试加载，但默认不发键；初始文件不存在也能正常打开工作台选文件。更新源码后请手动重新构建前端并重启这一次服务，否则看到的仍是旧页面；之后换模型不需要重启或改命令行。

顶部换模型流程：

- 「选择本机模型」：先暂停并松键，再打开游戏电脑的 Windows 文件窗口，可选任意位置的 `.pt`。取消选择不会换模型，也不会自动继续。窗口在后面时可用 Alt+Tab 切换；网页也有取消选择按钮。
- 「待加载模型」：显示本会话手动选过的文件及项目内已登记模型。选中仅代表准备加载，不代表已经更换。完整路径可悬停查看；顶部单独显示实际已加载模型及训练步数。
- 「加载模型」：确认后先检查新 checkpoint 的格式、权重及输入规格；校验失败保持旧模型和旧会话。通过后停止旧会话、保存未完小局片段，再创建新会话；加载完保持暂停。
- 「继续」：确认模型及游戏设置后点击，手动切回游戏。F10 或失焦会松键，恢复需要再次点击继续。停止 AI 不等于暂停游戏。

文件窗口调用 [Windows 原生文件选择接口](https://learn.microsoft.com/en-us/windows/win32/api/commdlg/ns-commdlg-openfilenamew)，没有另建 Tk 界面、没有上传或复制大模型，也不增加 GUI 依赖。只把用户明确选中的单个文件登记给浏览器，不开放任意路径读取。手选列表保留在本次服务内存，重启后可重新选；不修改 YAML 或模型文件。

浏览器提供四个模块：实战总览、战斗与动作、实战评估、参数与记录。评估页可选择两份历史报告，分页查看每局结果并比较条件。原有评估及参数页仍要求先暂停再应用。网页关闭/断线不等于关闭服务；使用顶部停止或终端 Ctrl+C 停止控制，文件选择窗口也会取消。

命令行可选参数仍然兼容；日常换模型用顶部选择，局数/推理设备可在参数页修改：

```text
python scripts/play.py --checkpoint outputs/cql_suika_joint432_v3/best.pt --rounds 20
python scripts/play.py --checkpoint outputs/cql_suika_joint432_v3/last.pt --device cuda --rounds 0
```

CPU 默认为 2 个线程。单帧小模型不保证 GPU 更快，用界面 P50/P95 判断；不因使用 GPU 自动改变决策频率。

无窗口模式会在连接到游戏后自动开始一次；F10/失焦后不自动恢复，无 GUI 时可以 Ctrl+C 退出后重启：

```text
python scripts/play.py --checkpoint outputs/cql_suika_joint432_v3/last.pt --headless --rounds 20
```

`--start` 可让浏览器模式在模型和游戏连接就绪后自动开始一次；`--port 8780` 可指定其他起始端口。通常推荐手动开始，先确认游戏模式与角色。

## 3. 配置与动作

所有路径相对 **soku_cql 项目根目录** 解析，不沿用 checkpoint 内 Linux 的数据/输出绝对路径。

`configs/live_eval.yaml` 的主要字段：

| 分组/字段 | 作用 |
|---|---|
| checkpoint | CQL 模型路径 |
| device / cpu_threads | 推理设备与 CPU 线程数 |
| output / rounds | 独立报告目录、目标完整小局数；0 为不限 |
| environment.player_side | left = 1P，right = 2P；需对应游戏人类控制侧 |
| self_character / opponent_character | 默认萃香 9 / 灵梦 0，防止控制错误角色 |
| battle_mode / battle_submode | 旧版固定值筛选已删除，旧 YAML 中出现时兼容忽略；主/子模式分别显示为诊断信息 |
| active_match_states | 默认 [2]，只有可战斗状态发模型按键 |
| cpu_difficulty_label | 手动填写游戏真实 CPU 难度，随报告保存；软件不会读取或修改难度 |
| decision_interval_frames | 默认 1，和 REP 每游戏帧训练口径对应；改大意味着按键保持更久、跳过中间观测 |
| max_inference_lag_frames | 推理后允许的观测落后帧数，超限丢弃并追最新帧，不发送陈旧动作 |
| max_memory_gap_frames | 大于该缺帧间隔就清空记忆，并标记统计不完整 |
| max_snapshot_age_ms | DLL 观测最大年龄，超过立即松键 |
| stale_timeout_seconds | 长时间没有有效更新的保护阈值 |
| watchdog_seconds | 推理/采样线程无响应时由独立看门狗松键 |
| focus_delay_seconds / poll_seconds | 聚焦安全延迟、共享内存轮询间隔 |
| keyboard | 四方向 + 六按钮的真实按键映射，不能互相重复或占用 F10 |
| restart | 自动续局开关、确认键、点按间隔和保持时长、超时与次数上限 |
| web.host / port / port_attempts | 实战本机监听地址、默认 8777 的起始端口、冲突尝试次数 |

模式枚举以仓库 `tools/SokuLib-dev/src/BattleMode.hpp` 为依据：主模式 2 为 `BATTLE_MODE_VSCOM`（人机），子模式 0/1 是 `PLAYING1/PLAYING2`，子模式 2 才是 `REPLAY`。实战跟随 PPO 的角色、`inBattle`、`matchState` 和 HP 校验；只按 Replay 子模式识别回放，不再把正常游戏子模式 1 错拒。主模式显示名和子模式显示名在总览及参数诊断中并排显示。

默认按键：上/下/左/右 = W/S/A/D；体术 = J；DASH = K；轻弹幕 = I；重弹幕 = L；切卡 = O；符卡 = P。O/P 是新增默认值，请先在游戏设置中核对。页面编辑后点击「应用并重新加载」才生效；长期保存请修改 YAML。

唯一Joint Q头在432个完整Controller State上argmax，decode回屏幕绝对九宫格、四战斗按钮和互斥卡命令。不随人物朝向翻转；Neutral为ID192。连续相同输出保持按键，不自动连点，不替换为236B等宏指令。切卡与用卡同时回读为1时，按与离线数据相同的规则仅清除切卡、保留用卡及其它按钮，再生成历史输入；不因此中断。发键端仍严格检查输出卡命令互斥，不实际发送双卡命令。

## 4. 输入、记忆与实时限制

基础输入和离线分片一致：18 个连续量、5 个类别量、9 个战术量，双方各选距萃香最近 3 个对象，每对象 8 个数值与 2 个类别及 mask。基础数值使用模型内归一化参数并裁剪到 [-10, 10]。Joint432版将双方四槽技能类型/等级、卡牌能量/数量、容量/已使用数、有序手牌ID/费用及mask放入Current Encoder，全部连续值使用训练集归一化。加入上一帧实际Controller Action embedding和上一帧方向组合持续时间clip60/60；不加入系统延迟。可选max_spirit/hitstop仅在训练集记录过时启用。旧checkpoint全部拒绝，见[资源模型](resource_model.md)。

GRU 在连续推理时保留记忆；暂停、失焦、局间、进程变化、明显缺帧或废弃的过期推理都会清空记忆。不载入离线训练过程中某段轨迹的临时隐藏状态。

这是普通 Windows 模拟键盘实战，**不是锁步模拟器，不能保证不漏帧，也不能保证每次都在一个游戏帧内完成推理**。观察 P95、漏帧、过期决策和按键回读；先关闭加速、其他控制器和重负载任务。原始 REP 动作对方向时序有要求；有输出不代表必然成功使出某招，不承诺仅接入实战就会提升模型效果。

## 5. 面板和报告怎么看

- 总览：完整局数、胜/负/平、胜率、平均伤害差与标准差。
- 当前局：累计造成/受到伤害、模型已发送决策数。
- 动作：432个完整动作的原始Q排序，支持Top20/Top50/全部；显示解码名称、会话/本局指令次数和回读帧数。数据/模型统计都按Joint Action计算。Q不是概率，指令次数和回读帧数分母不同。
- 回读确认：发送后更晚发布的观测中，方向和六按钮都符合预期才计确认；新动作覆盖前未看到匹配计未确认。未确认不能直接断言 SendInput 失败，可能漏帧或读取/发送时序不同。
- 实际 actionId：显示当前游戏动作、动作帧和进入动作的次数，不把按下攻击键等同于成功出招/命中。
- 耗时：最近至多 5000 次已发送推理的 P50/P95，包含状态整理、网络计算和 GPU 转 CPU 同步。
- 逐局效果：完整小局伤害差图，以及每条完整/片段记录。默认窗口展示最近 100 条，磁盘保留全量。

伤害累计按**同小局相邻有效观测 HP 的正向净扣减**计算，回血不计负伤害，负 HP 按 0 截断；不跨小局 HP 重置累计。不区分体术、弹幕或削血，不声称证明伤害来源。普通漏帧时累计只能代表观测区间净扣血，可能看不到区间内回血再受伤。超过记忆缺帧阈值等明显中断的局标为片段。

只有观察到开局边界、持续接管且捕获 HP 归零或分数增加终局的完整小局才计正式平均值/胜率。第一次在战斗中途开始、暂停、失焦、长缺帧或漏终局，都保留片段但不混进正式比较。默认完成 20 个完整小局后松键暂停；第一局中途接管不会算在这 20 局里。

每次加载都创建独立目录：

```text
outputs/evaluations/<时间-随机编号>/
  session.json   模型路径、SHA256、训练步数、设备、评估配置和统计口径
  rounds.jsonl   逐小局/片段：结果、伤害、动作计数和数据完整性
  summary.json  完整小局汇总、推理耗时、会话动作计数
```

每局/片段结算、点击保存、停止时保存汇总。保存只写报告，不写模型；同一模型重复评估也不会覆盖旧会话。不是逐帧录像或完整奖励决策链记录。

## 6. 排查与人工验收（本次未运行）

1. 模型加载：新版Joint432 CQL checkpoint可载入；旧CQL/PPO/DQN、不存在文件、结构不符和坏归一化参数明确拒绝。
2. 输入对齐：将同一原始帧通过 CSV/NPZ 与实战转换，人工比较 18/5/9 和最近对象的顺序及数值。
3. 按键：九方向和六按钮与游戏设置逐一核对，特别是 O/P；观察模型选择、回读和实际 actionId 的区别。
4. 固定权重：同一 checkpoint 评估前后文件哈希不变；不存在优化器创建或训练样本写回。
5. 安全：切出游戏/F10/点击停止/终端 Ctrl+C/推理失去响应时全部松键；失焦后不得自动恢复控制。网页断开不自动停止，重连也不自动继续。
6. 过期帧：终局、暂停、旧 DLL 发布停止、推理超时均不把旧动作送到新局或其他窗口。
7. 统计：中途接管、暂停和明显缺帧均单列；伤害不跨 HP 重置累计；不能用片段统计制造完整局胜率。
8. 续局：第一小局倒地不操作菜单，整场两胜/两负结算才连续按 Z；下一场战斗立即停止菜单点按；超时主动停止。
9. 报告：达到目标局数后保持暂停，`last.pt` 未改动；多个模型/多次会话结果分目录保存。
10. 小屏：1024×768 与 1366×768 下顶部操作可见，动作表局部滚动，趋势支持拖动范围窗口。
11. 模式：主模式 2 配合子模式 0/1 均能进入实战；子模式 2 才明确提示 REP。旧 YAML 的固定值不再触发误拦。
12. 浏览器：端口占用自动换端口；重复请求编号不重复切换模型；换模型和停止失败时仍保证松键。报告缺少难度或条件不一致时不判定谁更强。
13. 图形化选模型：初始文件不存在也能打开页面；桌面/其他盘/中文及空格路径均可选择。仅选择或取消不切换模型；加载坏文件后旧模型仍可继续。网页刷新后能找回本会话原生窗口选中的文件。
14. 窗口取消：原生文件窗口打开时，网页取消、停止及终端 Ctrl+C 能关闭窗口；重复点击不产生多个窗口，取消后不自动继续控制。选择和加载分开，1024×768 下两者按钮及实际模型名可见。
