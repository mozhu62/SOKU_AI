# BC 实战增量 TCN

## 结构与范围

当前 TCN 的 projection、stem 和残差块均使用逐帧通道 LayerNorm，统计不跨时间维；因此可以逐层缓存卷积输入。当前卷积 kernel=2，每层缓存 dilation 个输入位置。训练前向、模型参数与 checkpoint 格式不变。

实战仍要求真实连续的 32/256 帧观测。首次推理计算完整窗口；后续只计算新增帧，并更新每一层缓存。若积压多帧，一次计算新增片段。补收的历史帧不逐个发送动作，只使用最新输出。

换局、缺帧、重新加载模型时清空缓存。暂停期间继续采集；若未计算的帧已经离开观测窗口，下次推理重建完整窗口，不能跳过这些帧继续沿用旧缓存。缓存不写入 checkpoint。

## 精度与对照

`configs/live_eval.yaml`：

```yaml
amp: true
streaming_tcn: true
```

CUDA 使用 FP16 autocast，CPU 实际仍为 FP32；不执行 model.half()，Embedding 索引保留整数。关闭 amp 可对照 FP32，关闭 streaming_tcn 可对照原全窗口计算。网页参数页可修改，暂停后应用会重新加载并建立新会话，避免混用缓存。

FP32 增量算法在当前结构下数学等价，但不同运算布局可能产生浮点舍入差异；FP16 也不保证与 FP32 完全一致，接近的候选动作可能交换排名。
