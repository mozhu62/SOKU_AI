# 固定缓存与 CUDA Graph

实战新增 `tcn_cuda_graph: true`（兼容配置默认开启）。仅 CUDA/hybrid 且 streaming_tcn=true 时使用，CPU 保留参考实现。关闭可恢复旧增量路径。网页参数页可切换，应用必须重新加载会话。

加载模型期间预热并捕获单帧 TCN graph。每层卷积拥有固定地址缓存和工作区，以 copy 更新，不在稳态 Python 路径逐层 cat/clone。卷积、归一化等中间张量由 graph 内存池复用；并不意味着没有 kernel 或设备复制。每个新增真实帧一次输入复制和 graph replay，多帧按顺序处理，不丢帧、不重复补假帧。

首次满窗使用参考批量路径初始化每层缓存，并覆盖捕获期间的假历史。换局/缺帧只重置历史有效性，保留已捕获图，下次满窗重新初始化。历史视野、模型结构、checkpoint、训练前向不变。

CUDA Graph 捕获失败会中止加载，不静默回退。关闭开关后可以恢复旧路径。当前捕获精度固定于加载时；修改 AMP 或设备必须重新加载。

诊断阶段名后追加本次新增帧数，分别汇总，避免把补算1帧和多帧混在一起。后端在参数页显示 cuda_graph/eager。完整窗口初始化仍计为重建，不应拿来判断稳态延迟。CUDA 时间线不是纯 kernel 时间。

本次未运行编译、测试、游戏或性能验收。应人工验证 FP32 对照误差、AMP 动作差异、重置后输出、积压多帧、GPU 内存稳定性与总 P50/P95。不能据源码修改承诺已经达到60Hz。
